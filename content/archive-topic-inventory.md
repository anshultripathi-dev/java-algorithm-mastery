## Slide discrepancies found and corrected

- **How Java Works: Source, Bytecode, JVM, JRE, JDK** (`m0-how-java-works`): The slide "Why is JAVA slow?" says Java is slow because linking happens at run time; modern JVMs with JIT compilation are competitive with C++ for long-running programs. Start-up time is where Java is slower.
- **What Is an Algorithm?** (`m0-intro-algorithms`): The Introduction deck is a single definition and one MCQ ("What is an algorithm?" answer: b). The properties listed here are the standard textbook definition.
- **Arithmetic, Assignment and Increment Operators** (`m1-operators-arithmetic`): The "Basic I/O & Operators" deck introduces printing, input and arithmetic together; operators are covered here and I/O in the next two lessons.
- **Input: Scanner, BufferedReader and Command-Line Arguments** (`m1-input-scanner`): The slide example `avg = (args[0]+args[1]+…)/5` does not compile (String / int); the slide then fixes it with Float.valueOf — as the lesson shows, convert BEFORE adding.
- **Input: Scanner, BufferedReader and Command-Line Arguments** (`m1-input-scanner`): On the Console slide the code `System.console().readLine()` returns null in IDEs and when input is piped; use Scanner for programs that must work everywhere.
- **One-Dimensional Arrays** (`m2-arrays-1d`): The Block Swap slide introduces arrays using C-like syntax (`Int Arr[5]= {…}`, `Char Arr[7]={…}` with only 6 initialisers). Java declares `int[] arr = {…};` and the size is taken from the initialiser.
- **Number Systems, Binary and Two's Complement** (`m2-number-systems-binary`): The Booth deck revises binary addition and two's complement only as screenshots (21 → 10101 by repeated division); this lesson makes those prerequisites explicit.
- **Merge Sort and Divide and Conquer** (`m4-merge-sort`): Merge sort is not itself a slide topic; it is added because divide and conquer (Karatsuba, quick sort) needs a clean worked example and "merge sort" appears in the lecture's Big-O cheat sheet as the O(n log n) example.
- **Time Complexity and Big-O Notation** (`m4-complexity-intro`): The slide on the time-complexity chart says quadratic time complexity "increases exponentially with the input size"; quadratic is polynomial.
- **Time Complexity and Big-O Notation** (`m4-complexity-intro`): Slide 10 attributes O(n²·2ⁿ) to brute-force travelling salesman and slide 11 O(n!); both describe brute-force enumeration — the Held–Karp DP achieves O(n²·2ⁿ).
- **Analysing Loops: Counting Iterations** (`m4-complexity-loops`): Slide 22: the written derivation of O(log² n) is incorrect; the total is O(n log n) (the multiple-choice option C is the right one).
- **Analysing Loops: Counting Iterations** (`m4-complexity-loops`): Slide 26: option D (n⁴) is correct but the explanation concludes n³.
- **Analysing Loops: Counting Iterations** (`m4-complexity-loops`): Slide 20 claims that with `break` the loop is O(n) — correct — but its prose says "the inner loop always runs only once", which is also correct; the worry is only the suggested answer list that omits O(n) in that choice set.
- **Analysing Loops: Counting Iterations** (`m4-complexity-loops`): Slide 33 correctly derives O(√n) for `s = s + i`.
- **Space Complexity and the Call Stack** (`m4-space-complexity`): Slide 9 answers O(n) for recursive fibonacci space — correct (depth n), but the printed reason talks about "recursive calls n times"; precisely it is the depth of the call tree, n, not the number of calls.
- **Euclid's Algorithm (GCD)** (`a-euclid-gcd`): The slide pseudocode states the prerequisite "a > b". It is not needed: if a < b the first step swaps them (gcd(12, 50) → gcd(50, 12)).

## Assumptions made where slides were silent

- **Chinese Remainder Theorem** (`a-crt`): The slide's program takes the divisors first and then the remainders; the lesson programs use the same input order (`n`, then moduli, then remainders).
- **Booth's Algorithm (signed binary multiplication)** (`a-booth`): The slides use M = 0111, Q = 0011 (n = 4) and a second example with M = 01011, Q = 01110 (n = 5). Both are supported by the program.
- **Segmented & Incremental Sieve** (`a-segmented-sieve`): The slide describes the incremental sieve only in words ("check N + i using primes up to L"). The lesson implements the standard incremental (dictionary-based) sieve and labels it as such.
- **Majority Element (Boyer–Moore Voting)** (`a-majority-element`): The slide deck is a set of images from an IDeserve lecture; the Java fragments in the screenshots are reconstructed into the complete program `BoyerMoore.java`.
- **Maximum Equilibrium Sum** (`a-equilibrium-sum`): "Maximum equilibrium sum" is taken as the maximum of the equal side-sum (the deck's code). The prefix-including-a[i] reading is shown as a labelled variant.
- **Alice's Apple Tree (Minimum Garden Perimeter)** (`a-alice-apple-tree`): The problem statement is only given in diagrams on the slides; the lesson uses the standard statement (square centred at the origin, tree at (i, j) with |i| + |j| apples).
- **Manacher's Algorithm (Longest Palindromic Substring)** (`a-manacher`): The unfinished Java fragment on the slide is replaced by the standard algorithm; the explanation follows the 12 steps on slides 3–4.
- **Knight's Tour & Warnsdorff's Rule** (`a-knights-tour`): The deterministic tie-break (first move in the DX/DY list) is an educational simplification of the slide's randomised version.
